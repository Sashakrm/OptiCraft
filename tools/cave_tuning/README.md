# Подбор параметров пещер

Маленькая независимая утилита для подбора `freq`/`kTunnelBand` в
`World_Generator::cave_density_at` (src/world/generation/World_Generator.cpp) — тех самых двух чисел,
которые определяют, получаются ли пещеры настоящими протяжёнными ходами или рассыпаются
на отдельные несвязанные дырки. Использует тот же `noise3_XZBeforeY`/`fbm3` и тот же сид,
что и движок, так что результат отсюда напрямую переносится в код генератора.

## Сборка

```
./build.sh
```

## Использование

```
./cave_tune sweep
```
Таблица по набору кандидатов `(freq, band)`: `carved%` — сколько объёма вырезано,
`#comp` — на сколько несвязанных кусков это распалось, `largest_share%` — какая доля
всего вырезанного объёма лежит в одной связной системе. Высокий `largest_share%` (60-90%+
при разумном числе компонент) — признак настоящих протяжённых ходов, а не шума. Именно так
и был найден исходный баг: при band=0.045 (значение, которое было в коде) largest_share
получался в единицы процентов при сотнях компонент — то есть почти всё вырезанное было
рассыпано по одиночным вокселям.

```
./cave_tune slice <freq> <band> [y]
./cave_tune vslice <freq> <band> [z]
```
ASCII-срез сверху (`slice`, план на высоте `y`) или сбоку (`vslice`, разрез на глубине `z`) —
глазами проверить, что получаются извилистые тоннели, а не блобы/шум.

Подобрали числа получше — впишите их в `cave_density_at()` (`freq` в оба вызова `fbm3` для
`n1`/`n2`, `kTunnelBand`). `y_stretch` (сейчас 1.4, множитель для Y перед fbm3) зашит в
`tunnel_at()` внутри этого инструмента — поменяйте там же, если решите его тоже покрутить.
