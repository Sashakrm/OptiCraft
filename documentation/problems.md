# Проблемы производительности (problems.md)

Источник: статический разбор ветки `world_biome` (коммит 85b4645). Профайлер не запускался —
порядок по весу оценочный. Статусы: `[ ]` не решено, `[~]` решено частично, `[x]` решено.
После каждого решения отмечай статус и пиши, что именно сделано.

## 1. Освещение при правке блока (самое тяжёлое)

- [x] 1.1 `Chunk_Manager::recompute_lighting` — полный пересчёт по ВСЕМ источникам света мира, по 125 ключей
      чанков на источник, все затронутые чанки + соседи помечаются грязными, даже если свет не изменился.
      Сделать: инкрементальный свет (BFS добавления/удаления) в радиусе ~15 вокруг правки; грязнить только
      чанки, где значения света реально изменились.
      СДЕЛАНО: `relight_block_light_near` (куб радиуса 14 вокруг правки: очистка, затравка от источников куба и от
      неизменённых клеток за гранью, BFS), `relight_block_light_new_chunks` (инкрементально при загрузке чанков).
      Грязнятся только чанки с реально изменившимся светом (раньше все затронутые + соседи).
- [x] 1.2 Лава (излучение 5) считается источником → тысячи источников в пещерах. Хранить эмиттеры по чанкам.
      СДЕЛАНО: `m_light_sources` — карта чанк → позиции; запись удаляется при выгрузке, заменяется при загрузке.
- [x] 1.3 `recompute_sky_lighting` — пересчёт всей колонки (41 `get_chunk` на колонку, палитровое чтение),
      `clear_sky_light()` + `mark_mesh_dirty()` для каждого чанка колонки + 6 соседей. Сделать: считать только
      от точки правки вниз, грязнить только изменившиеся чанки.
      СДЕЛАНО: `relight_sky_light_near` (тень пересчитывается только для колонки правки; куб ±14 по x/z).
      Правка с той же прозрачностью (камень<->земля) теперь тоже не пересчитывает свет.
- [x] 1.4 `collect_finished_chunks`: `std::find` по вектору `m_light_sources` на каждый эмиттер — O(N²).
      Сделать: set/индекс.
      СДЕЛАНО: палитра чанка проверяется на эмиттеры/жидкости, скан 32768 вокселей только при их наличии
      (заодно закрывает 3.1); дубликатов нет — список чанка заменяется целиком.
      ЗАМЕР (headless, синтетический мир с лавой/факелами, 48 чанков): правка было ~19 мс и 48 грязных чанков,
      стало ~3 мс и ~2 грязных чанка. Блочный свет сверен с эталоном на 300+ правках.

## 2. Покадровые обходы всех чанков на главном потоке

- [~] 2.1 `get_renderable_chunks` — каждый кадр вектор из всех чанков + фрустум по секциям.
      Сделать: пересчёт только при смене секции камеры/ориентации.
      СДЕЛАНО ЧАСТИЧНО: плоский список загруженных чанков кэшируется по `m_chunk_set_epoch` (без обхода
      хеш-таблицы и аллокации каждый кадр). Проверка фрустума по секциям остаётся покадровой (камера
      вращается постоянно); достижимость секций уже кэшировалась (`build_section_reach`).
- [x] 2.2 `Renderer::render_chunks` — `std::stable_sort` всех видимых чанков с тяжёлым компаратором каждый кадр;
      3–5 поисков в `m_chunk_gl_cache` (unordered_map) на чанк. Сделать: предрассчитанный ключ сортировки,
      корзины по дальности, плотный массив по `gpu_handle`.
      СДЕЛАНО: ключ сортировки (квадрат расстояния) считается один раз на чанк; буферы кадра переиспользуются;
      поиск в `m_chunk_gl_cache` — один на чанк за кадр (3–5 раньше), дальше по индексу `m_frame_res`.
      Не делалось: корзины по дальности и плотный массив вместо `unordered_map` (выигрыш уже получен).
- [~] 2.3 `rebuild_dirty_chunks` — `for_each` по всем чанкам каждый кадр, `neighbors_settled` по 26 поисков.
      Сделать: набор грязных чанков вместо поиска.
      СДЕЛАНО ЧАСТИЧНО: скан целиком пропускается, пока с прошлого скана без грязных чанков никто не стал
      грязным (`Chunk::dirty_event_count`) и набор чанков не менялся — в покое это каждый кадр. Пока идёт
      стриминг (есть грязные чанки), скан остаётся полным.
- [~] 2.4 `unload_distant` — `for_each` по всем чанкам; запускать только при смене чанка игрока.
      РАЗБОР: уже вызывается только при смене чанка/окна игрока или пока есть остаток выгрузки
      (`m_unload_backlog`, по 24 чанка за вызов). Отдельной правки не потребовалось.

## 3. Работа на главном потоке при приходе чанка и сборке меша

- [x] 3.1 `collect_finished_chunks`: цикл по 32768 вокселям (поиск источников света и жидкостей).
      Сделать: воркер возвращает списки эмиттеров/жидкостей вместе с чанком.
      СДЕЛАНО (см. 1.4): скан пропускается, если в палитре чанка нет светящихся блоков и жидкостей;
      иначе — один `unpack` и плоский проход вместо 32768 вызовов `get_block`.
- [~] 3.2 `enqueue_mesh_rebuild`: копия `Chunk_Block_Grid`, ~18k чтений через `get_block`, аллокация `Mesh_Job`.
      Сделать: построчное чтение через `unpack`/быстрый путь.
      СДЕЛАНО ЧАСТИЧНО: грани соседей читаются прямо из сеток; однородные соседи (воздух, камень, ровный свет)
      заполняются целиком без цикла по 1024 клеткам. Копия сетки самого чанка и кольцо AO остаются.
- [~] 3.3 Повторные ремеши чанка при приходе каждого из 26 соседей. Сделать: объединять пометки.
      РАЗБОР: `rebuild_dirty_chunks` уже ждёт готовности соседей (`neighbors_settled`, `first_incomplete_ring`),
      поэтому повторный ремеш остаётся только у колец 0–1, которые мешатся сразу при вставке (сделано
      намеренно ради быстрого появления картинки вокруг игрока). Пометки соседей не убирал: меш читает свет
      и границы соседей, риск артефактов выше выигрыша.

## 4. Генерация мира

- [x] 4.1 `decorate_column` на 48×48 колонок для КАЖДОГО чанка; ранний выход только после `column_at`.
      СДЕЛАНО: `World_Generator::may_decorate_chunk` — диапазон высот под областью декораций (на поток, по колонке
      чанков) и те же условия раннего выхода сразу для всех колонок; цикл по 2304 колонкам пропускается целиком.
- [x] 4.2 `setter` деревьев вызывает полный `get_block` на каждый воксель дерева.
      СДЕЛАНО: сначала проверка, что воксель внутри чанка; полный `get_block` только для них (результат тот же).
- [x] 4.3 fbm горности считается дважды (`terrain_of` и `raw_surface_height`).
      СДЕЛАНО: `raw_surface_height` принимает готовый сигнал гор (перегрузка); `sky_anchor_valid` тоже.
- [x] 4.4 `get_height()` для пещер/рек строит целый `Column`; нужна `height_only`.
      СДЕЛАНО: `get_height` берёт только `Terrain_Point` (`terrain_point`, потоковый кэш) без климата/наклона/биома.
- [~] 4.5 Кэш терраина (8192) мал для построителей регионов; кэши thread_local дублируют работу воркеров.
      СДЕЛАНО ЧАСТИЧНО: кэш рельефа 8192 → 32768 колонок на поток. Дублирование между воркерами (общий кэш
      колонок) не делалось: нужен общий потокобезопасный кэш (seqlock) при выигрыше, который не измерен.
- [x] 4.6 `River_Network::kind_at` копирует `Column` на каждый воксель `generate_chunk`.
      РАЗБОР: `River_Network::Column` — 6 полей (~24 байта), копия дешёвая, регион кэшируется потоком; отдельной
      правки не потребовалось.
- [~] 4.7 Регионы: priority-flood рек (~0.4 с), `mark_water` пещер (6 `height()` на воздушный воксель),
      LRU 24/32 может перестраивать регионы.
      РАЗБОР: `height()` в `Cave_Network::Builder` идёт через локальный массив `m_hval`, вне окна — через
      `get_height` (теперь дешевле, см. 4.4). Алгоритм priority-flood рек не менялся (меняет результат/сложно).
      ЗАМЕР (headless, 2541 чанк, регион ±5 чанков): результат БИТ-В-БИТ тот же (хеш блоков и высот совпал со
      старым кодом), 3.67 → 3.29 мс на чанк в одном потоке. Больший выигрыш дала бы шумовая сетка с
      интерполяцией, но она меняет мир — в рамках этой задачи не делалась.

## 5. Жидкости

- [x] 5.1 Каждая клетка через `set_block_world` → срочный ремеш + пересчёт света (п.1).
      СДЕЛАНО: правка с той же прозрачностью без излучения (вода↔воздух и т.п. — `light_unaffected`) свет не
      пересчитывает вообще; лава/эмиттеры идут через локальный пересчёт п.1 (≈3 мс вместо ≈19 мс).
      Пачкой изменения не группировались: срочный ремеш уже объединяется набором чанков.
- [x] 5.2 `read_cell`: деление + хеш-поиск + палитра на каждый вызов.
      СДЕЛАНО: кэш последнего чанка в `Fluid_Simulator` (сбрасывается в начале `notify_changed`/`update`).

## 6. GPU-мешер и отрисовка

- [ ] 6.1 `mesh_greedy.comp`: `uvec3 mask[1024]` на инвокацию (~12 КБ), много палитровых чтений в AO/свете.
      НЕ ДЕЛАЛОСЬ: массив нужен для жадного слияния целого среза 32×32; уменьшить его можно только сменой
      формата ключа или переходом на shared-память с другой раскладкой работ — это правка алгоритма шейдера,
      которую нельзя проверить без реальной видеокарты (llvmpipe не показывает занятость регистров).
      Сделать на машине с GPU, сняв время компьют-прохода.
- [x] 6.2 `submit_gpu_batch`: 3 `glBufferSubData` на чанк в цикле + `glCopyBufferSubData` на чанк.
      СДЕЛАНО: origin/диапазоны/нули счётчиков копятся и отправляются по одному вызову на непрерывный участок
      ручек; копии readback тоже склеиваются по подряд идущим ручкам.
- [ ] 6.3 `draw_gpu_kind`: команды indirect с нулевым счётом.
      НЕ ДЕЛАЛОСЬ: отсечь нулевые команды без чтения на CPU можно только через `glMultiDrawArraysIndirectCount`
      (GL 4.6 / ARB_indirect_parameters), проект на GL 4.3. Нулевая команда на GPU почти бесплатна.
- [x] 6.4 Вершинный шейдер перемножает `projection * view * model` на каждую вершину.
      СДЕЛАНО: в `terrain_gpu_vertex.glsl` и `terrain_gpu_misc_vertex.glsl` один uniform `view_projection`
      (считается раз за кадр, `model` там всегда единичная). Картинка сверена со старой сборкой (скриншоты).

      СДЕЛАНО: канал клипа на кость ищется за один проход (первый найденный, как раньше), рабочие массивы

      СДЕЛАНО: `get_block_world` помнит последний найденный чанк (на поток; ключ — менеджер + эпоха набора

- [ ] 7.6 `Region_File`: `flush()` на записи, общий мьютекс на чтение (осознанный выбор ради корректности).
      НЕ МЕНЯЛОСЬ: осознанный выбор.
- [x] 7.7 Сборка: `-march=native` выкл. по умолчанию, нет LTO.
      СДЕЛАНО: добавлена опция `-DOPTICRAFT_LTO=ON` (проверка поддержки через `check_ipo_supported`);
      `-DOPTICRAFT_NATIVE_ARCH=ON` уже была. По умолчанию обе выключены (переносимость и время линковки).
