# Оптимизации освещения и потоковой обработки чанков

## Карта высот солнечного света

В `Chunk` хранится локальная карта `m_column_top_opaque`: для каждой из 1024 колонок X/Z она содержит Y верхнего блока, непрозрачного для солнечного света. Карта строится при генерации/чтении чанка и корректируется инкрементально при `Chunk::set_block()`.

`Chunk_Manager` объединяет локальные карты в кэш высот мировых колонок. Базовая высота обычного рельефа берётся из `World_Generator::get_height()`, а загруженные чанки уточняют её фактическими блоками — это учитывает пользовательские постройки, деревья и загруженные участки парящих островов. При выгрузке одной части вертикального столба кэш сохраняет последний известный уровень, пока в столбе остаются чанки.

Пересчёт прямого солнечного света использует карту высот вместо повторного поиска непрозрачного блока по вертикали для каждой клетки. Однородные чанки выше/ниже карты обновляются пакетно, сохраняя младший полубайт блочного света.

## Ленивое обновление после правки блока

Изменение прозрачности для солнечного света ставится в отдельную дедуплицированную очередь по мировым X/Z. Старый верхний блок фиксируется до изменения сетки, поэтому обработчик может определить точный диапазон, который мог измениться.

Очередь обрабатывает ближайшие загруженные колонки небольшими порциями: до одной правки за обычный кадр и примерно 2 мс на вызов. Правки выгруженных колонок остаются отложенными до следующей загрузки. Сам пересчёт очищает и восстанавливает небесный свет только в ограниченном радиусе вокруг изменения; горизонтальный BFS заново распространяет свет и корректно обрабатывает как осветление, так и затемнение.

Меши помечаются грязными только если итоговое значение света действительно изменилось. Соседний чанк получает отметку только при изменении клетки на соответствующей общей грани. Для пакетной заливки целого чанка отдельно отслеживается, какие именно из шести граней изменились.

## Подготовка мешей и очереди

- Метаданные соседнего чанка при подготовке граней копируются одним проходом по разреженному массиву, вместо повторного линейного `get_meta()` для каждой клетки грани.
- При появлении чанка соседние меши проверяются по контактной грани/ребру/углу. Пустые контактные области не запускают перестройку.
- Очередь приоритетов хранит битовую маску непустых корзин и пропускает пустые очереди блоками по 64, вместо полного перебора всех корзин при каждом извлечении.
- Приоритеты ожидающих мешей не пересчитываются каждые 120 мс, пока игрок остаётся в той же чанковой области.
- Применение готовых чанков ограничено небольшим числом за кадр и временным бюджетом, чтобы всплеск результатов генерации не занимал главный поток надолго.

## Основание по Tracy

В приложенной выгрузке профиля за 104 секунды были суммированы следующие зоны:

| Зона | Суммарное время |
| --- | ---: |
| `collect_finished_chunks` | 25,7 с |
| постановка перестройки мешей (`enqueue_mesh_rebuild`) | 21,8 с |
| копирование соседних граней (`enq_faces`) | 19,5 с |
| пересчёт солнечного света (`sky_light`) | 21,8 с |

Это суммы времени зон по профилю, а не прирост FPS и не время одного кадра. После изменений новый Tracy-профиль ещё не снимался, поэтому фактический процент ускорения здесь не заявляется.

- `git diff --check` проходит без ошибок форматирования патча.
- `Priority_Bucket_Queue` прошла стресс-тест с четырьмя producer- и четырьмя consumer-потоками: 200 000 элементов, без потерь и дубликатов.
